# Футболни прогнози

Автоматизиран сайт с прогнози за футболни мачове по статистически модели на Python.

**Пазари:** 1X2, над/под 1.5, 2.5 и 3.5 гола, ГГ (двата отбора вкарват), точен резултат, корнери (над/под 8.5–11.5) и value залози спрямо коефициентите.

**Първенства:** Англия (Премиър лийг, Чемпиъншип, Лига 1, Лига 2), Испания, Италия, Германия и Франция (по две дивизии), Шампионска лига, Лига на нациите.

## Как работи

```
football-data.co.uk ─┐                  ┌─ Dixon–Coles (голове) ─┐
  (резултати, корнери,├─ src/data.py ───┤                        ├─ src/predict.py ─ src/site.py ─ site/index.html
   коефициенти, програма)               └─ Poisson (корнери) ────┘         │
football-data.org ───┘  (ШЛ)                                        src/tracking.py (track record)
```

1. **Данни.** Сезоните се свалят като CSV от football-data.co.uk. Това са последните 3 сезона на всяка дивизия плюс `fixtures.csv` с предстоящите мачове и коефициентите им. Шампионската лига идва от API-то на football-data.org.
2. **Модел за голове (Dixon–Coles).** Всеки отбор получава сила в атака и в защита. Към тях се добавят домакинско предимство и корекция за резултатите с малко голове (0-0, 1-0, 0-1, 1-1). По-новите мачове тежат повече. Всички дивизии на една държава се обучават **заедно**, така новакът от Чемпиъншип идва в Премиър лийг със собствения си рейтинг.
3. **Модел за корнери.** Използва същата структура с Poisson разпределение върху корнерите.
4. **Пазари.** От очакваните голове се строи матрица с вероятността за всеки точен резултат. От нея се получават 1X2, над/под и ГГ.
5. **Value.** Вероятността на модела се смесва 50/50 с тази на пазара, т.е. коефициентите без маржа. Залогът се показва като value, ако предимството е поне 5%. Препоръчаният размер на залога е по ¼ Кели.
6. **Track record.** Всяка публикувана прогноза се записва в `data/log/`. След мача тя се оценява, а резултатите се виждат в таб „Резултати на модела“.

## Лига на нациите

Моделът за националните отбори се обучава върху всички международни мачове от последните 4 години. Източникът е [martj42/international_results](https://github.com/martj42/international_results). Приятелските мачове тежат наполовина, а мачовете на неутрален терен се смятат без домакинско предимство.

Предстоящите мачове се вземат от същия източник, ако вече са добавени там. Ако ги няма, копирай `nations_league_fixtures.example.csv` като `nations_league_fixtures.csv` и впиши мачовете. Имената на отборите са на английски, както в източника, например `Bulgaria` и `Republic of Ireland`. Разпознават се и някои други изписвания, например `FYR Macedonia` и `Ireland`. Датата може да е `24/09/2026` или `2026-09-24`. Мачовете без дата излизат в сгъната секция „Дата предстои“, а изиграните отпадат от нея автоматично. Когато UEFA обяви датите, достатъчно е да ги допишеш във файла.

Коефициентите за Лигата на нациите идват от [The Odds API](https://the-odds-api.com). С тях се изчисляват value залози за 1X2 и над/под 2.5. Безплатният план дава 500 заявки на месец, а сайтът ползва около 130. Регистрирай се, вземи ключ и го добави като secret `ODDS_API_KEY` в GitHub, по същия начин като `FOOTBALL_DATA_ORG_KEY`. Без ключ прогнозите се показват, но value залози за Лигата на нациите няма.

Рейтингите включват всички 55 европейски национални отбора. „Резултати на модела“ показва точността отделно за всяко състезание. Бектестът проверява модела върху мачовете от последните издания на Лигата на нациите. За тях няма исторически коефициенти, затова в бектеста няма сравнение с пазара и ROI.

За Лигата на нациите няма данни за корнери.

## Локално пускане

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python run.py backtest   # еднократно: проверка на точността (~1 мин)
python run.py all        # сваля данни, прави прогнози, генерира site/index.html
```

Отвори `site/index.html` в браузъра.

За Шампионската лига първо си вземи безплатен ключ от https://www.football-data.org/client/register и после:

```bash
export FOOTBALL_DATA_ORG_KEY=твоят_ключ      # Windows PowerShell: $env:FOOTBALL_DATA_ORG_KEY="..."
```

Тест без интернет, със синтетични данни:

```bash
python scripts/make_sample_data.py && python run.py all --offline
```

## Автоматично публикуване (безплатно, GitHub)

1. Създай хранилище в GitHub и качи проекта.
2. Отвори **Settings → Pages → Source** и избери **GitHub Actions**.
3. Отвори **Settings → Secrets and variables → Actions → New repository secret**. Името е `FOOTBALL_DATA_ORG_KEY`, а стойността е ключът ти.
4. Отвори **Actions → „Ежедневни прогнози“ → Run workflow** за първото пускане.

След това сайтът се обновява сам всеки ден в 08:00 българско време, а във вторник (16:00) и петък (20:00) още веднъж, веднага след като football-data.co.uk качи новата програма с коефициенти. Бектестът се обновява всеки понеделник. Адресът е `https://<потребител>.github.io/<хранилище>/`.

## Настройки (`config.py`)

| Параметър | Какво прави |
|---|---|
| `COUNTRIES` | Първенства и дивизии (кодове на football-data.co.uk: `SC0` Шотландия, `N1` Холандия, `P1` Португалия, `B1` Белгия, `T1` Турция, `G1` Гърция) |
| `N_SEASONS` | Колко сезона назад се обучава моделът |
| `TIME_DECAY_XI` | Колко бързо „остаряват“ мачовете |
| `L2_PENALTY` | Колко силно силите се „дърпат“ към средното |
| `VALUE_MODEL_WEIGHT` | Тегло на модела спрямо пазара при търсене на value |
| `VALUE_MIN_EDGE`, `VALUE_MAX_ODDS` | Филтри за value залозите |

Промени параметрите и пусни `python run.py backtest`. По-нисък log loss значи по-добър модел.

## Важно

- Букмейкърският пазар е много точен. Целта на един добър модел е да е близо до него и да хваща отделни неточности, а не да го бие във всеки мач. Реалната печалба се преценява по track record-а за поне няколкостотин залога.
- Шампионската лига има по-малко мачове на отбор, затова прогнозите там са по-несигурни. Отборите с малко данни се отбелязват на сайта и за тях не се дават value залози.
- Данните от football-data.co.uk са за лична, некомерсиална употреба. При комерсиален сайт провери условията или мини към платено API (напр. API-Football).

## Идеи за развитие

- xG данни (Understat/FBref) като допълнителен вход към модела.
- Gradient boosting (LightGBM) върху форма, xG, почивка и отсъстващи, в комбинация с Dixon–Coles.
- Коефициенти за корнери и ГГ от платено API, за да има value и за тези пазари.
- Известия в Telegram за нови value залози.
